# Domain docs

This is a single-context repo. Its domain vocabulary belongs in `GLOSSARY.md` at the root, and architecture decisions belong in `docs/adr/`.

Before working in an area, read the relevant glossary entries and ADRs if those files exist. Proceed without comment when they do not; create them when terms or decisions are actually established.

Use the glossary’s terms in issues, proposals, code, and tests. Surface any conflict with an existing ADR instead of silently overriding it.
